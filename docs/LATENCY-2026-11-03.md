# Approved completion latency changes

Only optimization proposals 3 and 4 were approved and implemented.

- Clipboard delivery and the initial auto-paste attempt run before encrypted
  history persistence. History remains synchronous, follows in `finally`, and
  still saves a take if copying fails. A modifier-delayed auto-paste retains its
  existing timer and guards. The history-off recovery text is retained immediately.
- Finalization and successful-transcript export use a 50 ms poll interval instead
  of 100 ms. Other phases, including recording, cancellation/discard, startup and
  composer clearing, retain their existing interval. Faster custom test intervals
  are preserved. Both intervals are clamped to at least 1 ms.
- The 700 ms composer settling window, hold cadence, deadlines, clipboard retries,
  stale-export deletion, export freshness checks and on-demand behavior are unchanged.
- Idle sleep and screen parsing caches were rejected by the user and were not changed.

These remove history persistence from the copy path and reduce completion detection
granularity. No live before/after latency reduction is claimed.

Review also corrected adjacent result feedback: an auto-paste rejection rechecks
the clipboard sequence before offering Ctrl+V, and changing auto-paste settings
settles a pending copied result instead of leaving the loading indicator visible.

Validation: full offline suite passes, including 436 engine assertions, 381 UI checks,
61 startup checks, Core/Audio/Wiring and harness groups. An existing handoff reparse
test remains skipped because link creation is unavailable. New scheduling checks
exercise every phase/purpose combination, preserve faster custom intervals, and
check the unchanged settling/hold defaults. History ordering was checked directly
in the completion flow; no real clipboard or microphone was operated by the tests.
