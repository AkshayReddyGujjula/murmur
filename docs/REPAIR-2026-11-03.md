# Murmur launch repair, 3 November 2026

## Reproduced defects

- `TrayIcon` assigned `ToolStripRenderMode.Custom` to both the root menu and
  submenus. .NET Framework throws `NotSupportedException` for that assignment;
  assigning `Renderer` is the supported way to select custom rendering. The root
  assignment ran before the notification icon became visible.
- `OnTakeTranscript` accepted stale take IDs. A completion queued before Esc could
  copy a cancelled take after the UI had already cancelled it.
- Startup had no exception boundary or durable error report. An explicit launch
  and a duplicate launch also gave no dependable visible confirmation.
- Shortcut registration failure was only a transient notification, while the menu
  continued to say that the unavailable shortcut worked.
- Empty exports silently disappeared, and missing-composer redraws could trigger a
  false no-speech failure. Both now have regression coverage and bounded recovery.
- A discarded handoff that could not be deleted was reused as though cleanup had
  succeeded. It now logs the retained path and recycles the owned session. A file
  locked by another process may remain until that lock is released.
- Optional delayed auto-paste had no target/focus guard or cancellation. It now
  checks the original target, clipboard sequence and modifier state, and a new take
  or shutdown cancels the pending timer. It remains off by default.

## Verification evidence

- Baseline offline tests passed despite the startup defect: those tests exercised
  menu models but never constructed the actual tray menu.
- The new real-menu constructor regression runs with the notification icon hidden.
  Restoring either invalid setter separately makes that test fail with the original
  `NotSupportedException`. The repaired menu passes, including nested submenus.
- The stale-transcript callback test failed before the take-ID guard and passes
  after it. Its dependencies are deliberately absent, so a stale callback must
  return before touching any device, clipboard, history, or UI.
- The normal test command now includes wiring and startup groups.
- Duplicate reveal uses a named event and a registered wait, with no idle poll
  timer. Hidden tests check signal delivery and wait-registration teardown.
- The engine group passes 403 assertions, including empty-export failure, redraw
  recovery, and recycling after a locked discard. No provider process is used.

## Review triage

Review suggestions are checked against the implementation before applying them.

- Rejected an automatic shortcut fallback: Ctrl+Space is the user's preference.
  Failures remain visible and the menu provides start/stop/cancel actions instead.
- Rejected the claimed EndTake-before-BeginTake ordering bug: the same UI thread
  enqueues BeginTake first, and the engine processes its FIFO queue serially.
  A 1.5-second transcription watchdog would cancel legitimate finalization.
- Rejected the claim that unloading an on-demand child necessarily contaminates
  the next take: the next child receives a new session, and the editor helper
  clears the exported draft. Existing recycling/discard guards remain in place.
- Removed a worker's autostart-detection proposal: a registered Run entry cannot
  distinguish an explicit double-click from a Windows login launch. Quiet launches
  must use an explicit `--background` argument.
- Kept the cancellation settling window: checking an empty composer before a new
  hold cannot exclude late words arriving from the old take after that check.
- The engine API intentionally supersedes an older unfinished request when a new
  one is begun. The tray ignores further start presses while finalizing; changing
  that queue contract is deferred rather than silently enabling overlapping takes.
- Rejected a proposed extra TaskbarCreated listener: the installed .NET Framework
  `NotifyIcon` already exposes its internal `WM_TASKBARCREATED` message handling.
- Rejected the claimed unprepared-header leak: Microsoft's documented contract
  says unpreparing a buffer that was never prepared returns zero and has no effect.
  See [waveInUnprepareHeader](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/nf-mmeapi-waveinunprepareheader).
- Existing Windows startup entries are left untouched. Entries created through the
  updated menu include `--background`; older entries can be refreshed by toggling
  Start with Windows off and on. No registry migration runs during launch.

## Follow-up checkpoint

- Audio driver setup/teardown now runs on an owned background worker. At most one
  physical session and one replaceable pending request exist. Fake-driver tests
  cover blocked opens/closes, restart storms, close failure, callback suppression,
  concurrent shutdown, and TickCount wrap/long uptime. Independent stress review
  found no blocking lifecycle defect. A permanently hung driver still requires
  restarting Murmur; resources still owned by that driver are never forcibly freed.
- Overlay frames, scratch arrays, memory DC and DIB are reused for the same size.
  Hidden tests cover pixel conversion, allocation failure, resize and disposal.
  Independent review found no blocking graphics or failure-wiring defect.
- The user reported an absent tray icon despite a running app. Read-only checks
  on 3 November at 13:15 confirmed the owned Murmur process was alive, and its log
  reported two successful takes/copies. No clipboard contents were inspected.
  Shell registration failure is a hypothesis, not a proven cause. The new build
  forces a fresh tray registration once after startup and on explicit reopen.
- After explicit user approval, only Murmur was gracefully restarted with the saved
  build on 3 November at 13:22 UTC. Startup log confirms Engine Ready and the tray
  registration refresh. Actual icon visibility still needs user confirmation.
  No recording, clipboard operation or Windows tray setting change was performed.

## Boundaries

No existing Claude session is inspected or operated. No microphone, clipboard,
account sign-in, installation, or settings operation is performed by these checks.
Visual acceptance and real speech-to-clipboard behavior still require a live take.
All branches and commits remain local. Unrelated files are preserved.
